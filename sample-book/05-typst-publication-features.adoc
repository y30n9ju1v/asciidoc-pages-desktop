== Chapter 5: Publication Semantics

This chapter exercises the closed publication semantics that AsciiDoc Studio
converts to SafeDocument data before PDF, HTML, or EPUB rendering. No Typst
code is embedded in the manuscript.

[#thm-safe-boundary]
[theorem]
.Safe output boundary
====
Every publishing renderer must consume only SafeDocument data and escape all
leaf text at its own output boundary.
====

The statement in <<thm-safe-boundary>> is a numbered, linkable theorem. For a
print-page reference use pageref:thm-safe-boundary[].

[#def-publication-intent]
[definition]
.Publication intent
====
An author declares semantic intent in AsciiDoc; the selected publication style
decides the visual treatment without accepting executable layout code.
====

[example]
.A safe example
====
The inline citation cite:[knuth1984] and the block in <<def-publication-intent>>
continue to work inside formal publication material.
====

[#alg-preflight]
[algorithm]
.Preflight routine
====
. Normalize the manuscript into SafeDocument.
. Report integrity and publication issues.
. Produce the final PDF only when blocking errors are resolved.
====

[proof]
.Why the model remains reviewable
====
The accepted node kinds and their fields are finite. A reviewer can therefore
reason about every path from a manuscript to the generated PDF.
====

[columns,columns=2]
====
=== Two-column editorial note

Use a column container only for short magazine or journal passages. Long book
chapters stay single-column for stable pagination and accessible reading.

The PDF renderer uses a fixed two- or three-column layout; HTML and EPUB use
CSS columns as a readable approximation.
====
